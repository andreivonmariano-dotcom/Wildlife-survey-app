# v0.16 acceptance plan: GNSS survey-start gate and taxonomy

Status: implementation submitted for automated build and physical-handset evaluation.
This checklist is not a claim that the device passes a 10 m horizontal error test.

## New survey GPS preflight
1. Fresh install and upgrade from v0.15.0. Do not uninstall v0.15. Export a complete ZIP before upgrading.
2. With location permission denied, select each survey type. The GPS screen must request precise access, not start a survey, and display guidance.
3. Grant approximate-only location on Android 12+. The app must keep Start disabled and request PRECISE access.
4. Turn location services off. Verify the screen says GPS unavailable, shows settings and retry, and creates no survey row.
5. Outdoors in open sky, watch successive GPS updates. At 10 m or worse, Start must remain disabled. At strictly less than 10 m and age <=10 s, Start becomes available.
6. Let an accepted fix age past ten seconds without another valid update. Tapping Start must reject it and retain the preflight screen.
7. Verify provider coordinates, horizontal accuracy and timestamp refer to an actual GNSS GPS_PROVIDER update, not a previously saved station, last-known location, network-only fix, or mock location.
8. After acceptance, survey setup should start the clock once and create precisely one survey row. Check source columns: start_gps_latitude, start_gps_longitude, start_gps_accuracy_m, start_gps_recorded_at.
9. Confirm cancelling from the GPS screen creates no survey and no point-count station visit.
10. Forest canopy trials: if 10 m precision is unavailable, show a meaningful status and keep the survey unstarted. Document location limitations. This release has no override that silently counts a poor fix as meeting 10 m.

## Satellite sky map and station-level GNSS monitor
- The GNSS view now plots real satellite azimuth and elevation, with true-elevation 30°/60° circles and cardinal directions. Satellite label prefixes identify constellations; marker colors identify GPS, Galileo, GLONASS and BeiDou. The green outline marks satellites used in the latest fix. Marker size reflects C/N0 rather than claimed positional accuracy.
- Android GNSS status requires device hardware support and precise location permission. Confirm counts and display on at least two handset models.
- Planned point counts, custom bird stations and structured herpetofauna/mammal stations use the continuously running GNSS receiver. A fresh qualifying fix starts the station directly. Otherwise a compact GPS check appears, without a sky map.
- The station timer begins only after a qualifying live GPS_PROVIDER fix with reported accuracy strictly below 10 m and age no greater than 10 s, or an explicit missing-GPS override.
- A missing-GPS override saves NULL coordinates and the `missing_or_weak_gps_at_start` status. It must never reuse a recent-looking fix from a different station.
- For each station type, inspect exported `point_counts.csv`, `sampling_units.csv`, `survey_stations.csv`, and `sites.csv`: coordinates/accuracy/timestamps must reflect that station's own accepted fix, or be NULL after an override.
- Cancel the GNSS monitor: no new station visit should begin and no false effort duration should accrue for that station.
- Return to the survey during an already-open point count: do not replace the historic station-start coordinate with the survey-level or latest background GPS fix.
- For repeat routes, retain original site coordinates. Capture the new visit in `point_counts` and `survey_stations`, and preserve comparison checks.
- Under heavy canopy, test retry, permission denial, GPS disabled, loss of signal, and explicit override separately. The 10 m threshold is a receiver-reported estimate, not verified field error.
- Check Android builds and physical handset acceptance before release.

## Database, history and backup
- Confirm new SQLite schema version 12 migrates existing v0.15 and preserves projects, routes, stations, photographs, records and timers.
- Existing historical surveys must have NULL for four new start GPS fields, not zero or fabricated coordinates.
- Compare the column count, header labels and row values in surveys.csv.
- Scientific data review should flag any new survey-start GPS row with incomplete coordinates or accuracy >=10 m, without editing records.
- Test simultaneous event restart / survey resume. Resume bypasses new-event preflight for already-started surveys, retaining original start location metadata.

## Taxonomy and provenance
- CI downloads the official MDD v2.5 CSV from Zenodo, validates published MD5, filters living wild species with Philippines (including uncertain country members as unreviewed), and bundles the offline mammal asset in the APK. Check the build log count (246 in the pinned release).
- Start a fresh installation and upgrade v0.15: Offline taxonomy should show 246 MDD national candidate names without manual import; verify scientific names contain spaces instead of MDD key underscores.
- MDD v2.5 official file MDD_v2.5_6904species.csv (DOI: 10.5281/zenodo.21654811): test the manual importer remains repeatable and does not damage the bundled catalog; inspect row count, countryDistribution, family, taxon ID and review flags.
- MDD taxa flagged for review must be marked unreviewed in catalog.
- Confirm no source imports declare Philippine-wide candidates as Mindanao- or province-confirmed occurrences automatically.
- Import an attributed Sy amphibian 2025-1 CSV and Sy reptile 2026-1 CSV only after access/licensing and data format are checked. Keep original taxonomy attribution and version.
- AviList v2026 bird CSV requires a separately curated Philippine membership filter before national deployment.
- Confirm recorded unknown identities and historical verbatim names survive catalog imports.

## Evidence before a field-ready designation
- Record handset model, OS, GNSS source, canopy / open sky, elapsed time to <10 m and fix accuracy at start.
- Compare sample handset locations with independent surveyed references. Android's reported accuracy is not the measured true error.
- Run CI unit tests and build; install APK on the same device that holds prior v0.15 data and inspect complete ZIP exports.

## v0.16.1 negative wall-clock age and foreground GPS regression
- The screenshot showed a reported ±3.8 m fix with age -0.2 s. Verify elapsedRealtimeNanos accepts an otherwise valid fresh fix independent of phone clock skew.
- With acquisition running, press Home or lock screen. Return through Recent Apps. The receiver must continue without resetting location acquisition.
- Check Android 13+ permission prompt, visible ongoing GPS notification and Stop GPS action.
- With a fresh fix at a new station, station setup must start directly without launching the GNSS sky map. With stale or inaccurate readings, show the short GPS check screen.
- During a transect effort pause, GNSS remains active but route-distance tracking does not accumulate segments. Finishing the survey ends the GNSS foreground service.
- Force-stop, reboot, permission changes and battery restrictions are expected interruptions to monitor on physical devices.
