# v0.15 acceptance plan

## Database and template migrations
- Back up v0.14.1 ZIP. Upgrade the app in place and check all historic projects, surveys, sites, visits, photos, tracks and observation counts.
- Create a brand-new installation. Compare database table structure with upgraded database, including route_templates and route_template_stations.
- Run Scientific data review and inspect PRAGMA quick_check results.
- Create a new Bird > Point Count survey with 2 km route and 250 m spacing. Choose Save this route, give it a unique name.
- Begin the survey, visit three stations, then mark incomplete. The saved route must remain available.
- Start a new survey under the *same project*, choose the saved route. Verify the same 9 station IDs are in both surveys, but new survey and point-count IDs and independent GPS visits.
- Start the new route and compare GPS station positions. If a new GPS position is far from a saved station, Scientific data review should flag it without overwriting the baseline.
- Switch to a different project and confirm the route list changes. Templates must not include stations from unrelated projects.
- Try reusing the same name for a new route. The UI should block duplicate project+name+method names.
- Confirm line transect and herpetofauna VES have no fixed-station route template choice.

## Survey timing and effort
- Total session timer must continue between point-count stations.
- Station point timer begins on arrival, pauses during intentional effort breaks and records overtime accurately.
- Save the survey, inspect observer_effort_minutes. The value must reflect actual sampled minutes summed across point counts, not time walking between points.
- Record insufficient sampling intervals and check that completion is flagged accordingly.
- Compare 2 km with 100 m (21 points), 250 m (9) and 500 m (5). Check custom nondivisible lengths do not add an extra station closer than configured spacing.
- Test navigating Home / backgrounding / resuming during a point. No additional stations should be generated on resume.

## Data quality
- Open Scientific data review. Check source records are not changed by scanning.
- Check raw ZIP includes data_quality_flags.csv, surveys.csv, route_templates.csv and route_template_stations.csv.
- Temporarily enter an incomplete GPS station and confirm it appears as a review flag.
- Test a changed manually edited station coordinate. Confirm the original GPS accuracy estimate is cleared and old point-count snapshots remain.
- Check a large station-revisit offset flags location drift but does not automatically mark the observation invalid.
- Confirm archives still retain Not Counted surveys and associated reasons, excluding them from analytical outputs.

## Mammal checklist
- Open Offline species checklist.
- Import `MDD_v2.5_6904species.csv` from the official July 28, 2026 release.
- Inspect the count, sample scientific names, families and provenance.
- Confirm MDD source rows NOT referencing Philippines are excluded.
- Confirm a species with only country-level evidence remains accessible in the complete species list and is not automatically marked as a Mindanao endemic.
- Confirm the wrong version or a malformed MDD CSV is rejected.
- Test an external attributed Sy checklist CSV, with source and version fields. Absence of island data must not become a negative occurrence statement.
- Confirm unidentified bird, reptile, amphibian and mammal entries remain available.

## Evidence, export and UI regression
- Test photo attachments and check images and photo index remain in ZIP.
- Test bird compass and bearing, GPS transect, timers, Not Counted long press, and station progress.
- Confirm offline operation with the phone in airplane mode; no map is required.
- Run route arithmetic unit tests, then compile the debug APK with the existing signing key.
