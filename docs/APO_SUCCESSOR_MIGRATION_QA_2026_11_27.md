## Permanent signer plan — not adopted

The new package ID is approved, but production signer adoption remains separate. Never create the permanent key in an ephemeral hosted runner, a public repository, or an ordinary Actions cache. Generate an owner-controlled encrypted PKCS#12 keystore with a strong unique password, a distinct production alias and suitable validity (proposed RSA 3072/25 years) on an authorized persistent workstation after the separate adoption decision. Store password in the owner's password manager, separately from keystore copies. Do not print password, private key or base64. Make an encrypted offline backup on an independent owner-controlled device/storage location, verify SHA-256 of both keystore copies and export the certificate from a recovered copy to match the intended signer. Verify that the key can sign and that APK verification yields that exact certificate. Document public certificate fingerprint, custody and recovery receipt only. If CI needs the signer, provision via restricted private-repository encrypted secrets, never upload private key as ordinary release artifact. Limit secret-bearing workflows to reviewed pinned source and trusted owner-dispatched main (never pull-request execution). Require package, version, signer, original source checks, offline use, complete data migration, failure tests and subsequent in-place successor upgrade tests. Keep production signing mode distinct from QA mode, and refuse distribution with QA key. Do not retire legacy app until owner separately approves after physical acceptance.
