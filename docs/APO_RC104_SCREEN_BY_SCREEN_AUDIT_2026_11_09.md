**Date:** 9 November 2026 (Asia/Manila). **Reviewed app:** draft PR #109, `feature/apo-rc104-phlibrary-large-text-v164`, exact application SHA `720b967003b30ac5bf70026526ea7fed57f11983`, code164, SQLite29. **Status:** audit and unapproved recommendations, no Java or APK change.

## Evidence scope
Inspected RC104 signed APK, unchanged RC103 normal-scale and RC104 320×720/200%-text Android14 Home/Explorer/Profile screenshots, and native source of the Home, Explorer, reader, filter dialogs, saved collection, bibliography, reference dialog, habitat index and profile. The latter supporting screens are **source-code reviewed only**, not emulator screenshot verified. No owner-phone, TalkBack or low-end performance tests performed.

## Confirmed issues

- **Reference navigation (high):** Book v1.82 contains **2,760 attached author–year citation fragments with no populated full field** alongside **1,159 separately stored original bibliography references**. Reader dialog forwards the whole short label into bibliography search, which is a literal lowercase substring matcher over source text. Independent RC104 APK text comparison found only **109/2,760 citation occurrences**, **6/380 unique short labels**, are exact substrings of any bibliography entry. This measures a *broken search handoff*, not true source coverage or whether the missing matches can be established. Even both `Ceyx mindanensis` citation labels fail literal lookup. Repair with documented author/year token matching, visible no-exact-match fallback, and reviewed citation-to-source crosswalks. Do not assign invented source IDs/DOIs.
- **Habitat linked-evidence coverage (high):** APK contains **15 habitat reference profiles** and **21 provisional literature edges involving 15 taxa**, linked to only **6/15 habitats**; 9 habitat pages have zero source-linked species. Source URLs and review flags are in the edge JSON but profile UI displays only a title and text, not an explicit opening URL or review state. Change the copy to `No reviewed links added yet`, expose traceable URLs and source types, and retain site-occurrence=false distinctions. A zero-link display does not prove species absence.
- **Home (medium; screenshot):** 282dp forest hero plus repeated book heading/counts consume much of the first screen; deeper functions (habitats, references, saved) sit below fold. Preserve original forest art and green/ivory identity but compact the hero, make primary entrypoints discoverable, reduce repeated introductory copy.
- **Explorer (medium; screenshot + code):** Large heading, multiple filter rows and chips crowd out results; at 320dp/200% font only part of one result is initially visible. Compact the header into sticky search and filters; make active rarity/IUCN visible in compact mode. `Clear all filters` in compact dialog fails to clear search query and sort while top Clear does. `1 accounts found` has a singular grammar bug. Empty saved/search states need guidance. Text matching includes whole article paragraph: label geography/habitat matches as textual mentions, never validated local occurrence. Consider indexed/debounced filtering for untested low-end performance.
- **Profile reader (medium; screenshot + code):** Long masthead, two conservation/rarity cards, and three repetitive natural-history labels push original article far below fold. Keep exact original single narrative, make reading start earlier, move Save near title, provide reading-position restoration. Source code shows related-family links rerender species inside a single `TaxonDetailActivity`; Back exits instead of stepping through viewed species. Reader's v1.82 record has global IUCN but no separate validated DENR field; do not infer national status.
- **Rarity / filter dialogs (medium; source only):** Discovery Rarity home chooser shows tier names but not their educational meaning or counts. Give a brief explanation, show actual badge counts 124/336/214/37/3/1, expand IUCN abbreviations, and unify filter controls with consistent reset behavior.
- **Saved collection (medium; source only):** Device-local name-keyed SharedPreferences saves reading selections but not stable taxon concepts. Offer empty-state guidance, quick access and a future explicit migration to reader concept IDs. Never remap historic survey observations.
- **Habitat index/detail (medium; source only):** Fifteen long cards, no grouping/search, reused forest art; group by the profile's existing categories. Header always shows `15` even on a specific habitat detail. Detail's `Search mentions in Book 01` uses hardcoded or first-word queries, not a verified habitat-to-species index. Use scannable sections with direct source links.
- **Bibliography (medium; source only):** Long source-text cards with literal substring search and raw original records are cumbersome. Use author/year/title previews, expanded details, original URLs and a clear unmatched-citation path. Preserve original bibliographic text.

## Cross-screen audit boundary and priorities

Existing contrast palette is generally readable (muted text on paper computes around 5.8:1) and the RC104 tested large-text clipping fixes passed. Do not change colors solely for novelty. Check TalkBack, small screens, font extremes, home/back navigation, empty cases, filters, bibliography, habitat pages, dark-system state, and actual reading flow on Android phones. No screenshots are presently available for non-core screens.

**Recommended order, not owner-approved implementation:** (1) compact navigation and reading-first Home/Explorer/Profile with consistent filters; (2) source navigation and habitat link transparency; (3) evidence indexing, book navigation history, concept-ID bookmarks and performance. Preserve canonical 715 Book 01 v1.82 text, Discovery Rarity v0.3.4, source evidence limits, Android ID/signing continuity and SQLite29. No new APK or user records changed during this audit.
